## 0. 專案定位 ✅

- **輸入方式**：注音（Bopomofo），標準大千排列（與微軟新注音相同）
- **使用者**：主要自用，以公開 repo 形式開源
- **平台**：Windows + macOS，**同一套行為、同一套快捷鍵、同一份設定**
- **輸出字集**：預設繁體，可切換簡體（只在輸出時轉換）
- **中英切換**：預設單按 Shift，可自訂
- **效能原則**：打字 / 選字路徑極低延遲；設定介面次要

## 2. 現有輸入法痛點 → 對應需求

| # | 痛點 | 推測根因 | 對應設計 |
|---|------|----------|----------|
| P1 | 用久了會壞，選字越來越亂 | 學習資料只增不減、無衰減 | 學習資料與詞庫分離、衰減、上限、可刪除 / 重置 / 備份 |
| P2 | 有建議詞卻亂選；常用字不在第一位 | 排序品質差、學習權重失控 | 可固頂、候選窗直接刪學習結果、**自動化選字準確率評測** |
| P3 | VS Code 按 `Ctrl+,` 出現全形逗號 | 輸入法把 Ctrl 組合鍵拿來輸出標點 | **Ctrl / Alt / Cmd 組合鍵預設一律放行**；標點不使用 Ctrl 組合鍵 |
| P4 | TUI / 遊戲中組字、候選窗位置錯亂 | 拿不到正確游標座標 | 多層定位 fallback、依 App 設定策略、自繪組字窗 |

## 3. 架構 🔶

```
             ┌──────────────── 輸入法服務程序（常駐、單一實例）────────────────┐
App 程序     │                                                               │
┌─────────┐  │  核心（Rust）：注音引擎 · 學習 · 設定 · 快捷鍵 · 遊戲模式      │
│ TSF DLL │──IPC──▶ 候選窗 / Emoji 面板繪製                                  │
│ (薄層)   │  │  AI 執行器（非同步，永不阻塞打字路徑）                          │
└─────────┘  │  Git 同步（背景）                                              │
             └───────────────────────────────────────────────────────────────┘
macOS：IMK 本身就是獨立程序，直接內嵌核心
設定 GUI：獨立程式，透過檔案 / IPC 與服務溝通
```

- **Windows 的 TSF DLL 會被載入到每一個 App 的程序裡**，所以 DLL 只做轉送，重的東西（引擎、SQLite、AI、繪圖）都放在服務程序
  - 好處：當掉不連累 App、AI 模型只載入一份、所有 App 共用同一份學習狀態
  - IPC 用 named pipe，每次按鍵一次同步往返（小狼毫做法）✅
  - **必須設逾時**：逾時就放行按鍵並標記服務失聯，絕不讓 App 卡住
  - DLL 端先在本地判斷能直接放行的按鍵（沒有組字中 + 非注音鍵），減少往返
  - Rust 與 Swift 之間用 **C ABI（cbindgen）** 🔶，Windows 與 macOS 共用同一份介面
- 詳細查證見 [research.md](research.md)

## 4. 規格細節

### 4.1 Shift 切換判定 ✅
- 單獨按下並放開 Shift、中間沒按其他鍵，才算切換
- `Shift+字母`、`Shift+滑鼠點擊` 不觸發
- 按住超過門檻（預設 300ms）才放開，不觸發
- 左右 Shift 可個別設定

### 4.2 簡體輸出 ✅
- 引擎以繁體組字與學習，**輸出時**才轉成簡體
- 使用 OpenCC 轉換表（含詞彙層級轉換，例如 軟體 ↔ 软件 可選）
- 可用快捷鍵或依 App 設定切換

### 4.3 遊戲模式 ✅
1. 焦點不在可編輯欄位時，自動放行所有按鍵
2. 全螢幕偵測，自動進入遊戲模式（系統 API 只偵測得到獨佔全螢幕，Win11 多數遊戲是無邊框視窗 → 另外比對前景視窗與螢幕大小；**輔助用，不可靠**）
3. App 規則清單（執行檔名 / Bundle ID）
4. 手動快捷鍵開關，系統匣 / 選單列顯示狀態

遊戲模式下：Shift 不切換、組合鍵全放行；可選「鎖定英文」或「保留目前狀態」。

### 4.4 中英預設狀態 ✅
- **全域預設**：中文 / 英文
- **App 規則表**（與遊戲模式共用同一張表）：

  | 欄位 | 說明 |
  |------|------|
  | App 識別 | Windows 執行檔名、macOS Bundle ID（同一筆規則可同時填兩個） |
  | 預設狀態 | 中 / 英 / 跟隨全域 |
  | 切回時 | 重設為預設 / 記住上次狀態 |
  | 遊戲模式 | 關 / 鎖定英文 / 保留狀態 |
  | 標點 | 跟隨全域 / 強制半形（例如程式編輯器） |
  | 輸出 | 繁 / 簡 |
  | 候選窗定位策略 | 自動 / 指定策略（P4） |

- 切換狀態時在游標旁短暫顯示「中 / A」提示

### 4.5 中英混打 🔶
候選方案（可組合）：

| 方案 | 做法 | 誤判風險 |
|------|------|---------|
| A. 臨時英文 | 組字中按 `Shift+字母` 進入臨時英文，空白鍵結束，整句一起送出 | 無 |
| B. 英文候選 | 按鍵序列剛好拼成英文單字時，在候選窗附上英文選項 | 無（使用者自己選） |
| C. 自動偵測 | 注音組不出合法音節、且像英文單字時，自動判為英文 | 中 |
| D. AI 判斷 | 用小模型判斷整段按鍵是中文還英文 | 低～中，有延遲 |
| E. 盤古之白 | 中英之間自動插入半形空格（可關） | — |

**決定** ✅：**B + C + E**（參考華碩智慧輸入法的「混合輸入模式」）
- C 的做法：每個按鍵序列同時以「注音」與「英文」兩種方式解碼並評分，取分數高者；B 列出另一種解讀作為備選
- 使用者修正自動判斷後，記住該序列的偏好（華碩也有類似的修正學習）
- 依 App 可關閉 B / C（華碩的使用者回報：英文候選窗會和開發工具的自動完成視窗重疊）
- 不採用 A（`Shift+字母` 強制英文），判錯時由 B 的候選修正

### 4.6 全形 / 半形標點 🔶
**前提**：大千排列中 `, . / ; -` 都是注音鍵（ㄝ ㄡ ㄥ ㄤ ㄦ），所以中文模式的標點必須透過別的鍵輸入。微軟用 `Ctrl+,` 輸出全形逗號，就是 P3 的元兇。

候選方案（可組合）：

| 方案 | 做法 |
|------|------|
| A. Shift 標點 | `Shift+,` → `，`、`Shift+.` → `。`，對照表可在設定檔自訂 |
| B. 標點選單 | 按 `` ` `` 開啟符號選單，用數字鍵選 |
| C. 模式綁定 | 中文模式全形、英文模式半形 |
| D. 獨立切換 | 快捷鍵單獨切換全 / 半形，與中英狀態無關 |
| E. 智慧標點 | 數字後的 `.` 輸出半形（3.14）、英文後的 `,` 輸出半形 |
| F. 成對補全 | 輸入 `「` 自動補 `」`，游標放在中間（可關） |
| G. 依 App | 程式編輯器強制半形（見 4.4） |

**建議**：A + B + C 為預設，D、E、G 可設定，F 預設關閉。**標點全部不使用 Ctrl 組合鍵**。

### 4.7 自訂資料夾 ✅
- **資料根目錄**（**設定檔**、辭庫、學習資料、模型）可放在任意位置 ✅
- **程式本體位置固定**（查證結果）：
  - Windows：TSF 註冊必須寫 HKLM → **安裝需要系統管理員權限**，DLL 放 `Program Files`
  - macOS：放 `~/Library/Input Methods`
- 用一個小的指標檔記錄資料根目錄位置
- macOS **不開沙盒**：沙盒會把檔案存取限制在 container 內，與自訂資料夾衝突 🔶

### 4.8 Git 同步 🔶
```
<資料根目錄>/            ← git repo
├─ config.toml           同步：快捷鍵、外觀、全域偏好
├─ apps.toml             同步：App 規則表（Win / Mac 識別碼並存，不衝突）
├─ dict/*.tsv            同步：使用者詞庫（一行一詞、排序固定 → 合併衝突最少）
├─ learning/<機器ID>.tsv 同步：每台電腦只寫自己的「彙總快照」，讀取時合併 → 永不衝突
├─ themes/               同步：候選窗主題
└─ local/                .gitignore，不同步
   ├─ machine.toml       單機：DPI、候選窗位置、模型路徑、硬體設定
   ├─ cache.sqlite       由同步檔案重建的快取
   └─ models/            AI 模型檔（太大不進 git）
```
- 背景自動 commit（防抖動）、啟動時 pull、定期 push
- 呼叫系統內建的 `git`，沿用使用者既有的 SSH / 憑證設定 ❓
- **API Key 等機密放作業系統鑰匙圈**，絕不進 git
- 發生衝突時保留兩邊並通知，不自動丟資料
- **學習資料儲存** ✅：
  - 本機一律以 SQLite 為主（不開同步也一樣）
  - 開啟同步時，才定期匯出成**彙總快照**（每個詞一行：詞、讀音、分數、最後使用時間），而不是逐筆事件 log
  - 快照大小只跟「詞彙量」有關，不隨時間無限成長（約數 MB 內）；git 只記錄有變動的行
  - 提交頻率限制（例如每小時一次），避免 git 歷史膨脹
- ⚠️ 學習資料等同打字內容的摘要，**同步用的 repo 必須是私人 repo**（與公開的程式碼 repo 分開）

### 4.9 快速加詞 / 刪詞 🔶
- 組字區用方向鍵選範圍 → 快捷鍵加詞
- 剛送出的 N 個字 → 快捷鍵叫出加詞視窗，可調整長度
- 選取已輸入的文字 → 快捷鍵加詞（透過 TSF / Accessibility 讀取選取內容）
- 多音字自動推算讀音，有歧義時讓使用者選
- 候選窗上 `Shift+Del` 刪除該詞 / 該學習結果
- 偵測到「常常一個字一個字選出同一個詞」時，主動建議加詞

### 4.10 Emoji / 符號表 🔶
- 面板：分類、**中文關鍵字搜尋**（使用 Unicode CLDR 繁中註解）、最近使用、膚色
- 候選內嵌：打「開心」時，候選窗尾端附上 😀（可關）
- 同一個面板也放特殊符號（①、→、℃）、顏文字
- 面板與候選窗共用同一個繪圖引擎

### 4.11 候選窗 🔶
- **常駐、預先建立、只更新內容**，不在打字時建立視窗
- 原生繪製：Windows 用 Direct2D / DirectWrite，macOS 用 Core Text ❓
- 可自訂（`themes/*.toml`）：直式 / 橫式、每頁數量、字型、字級、顏色、圓角、陰影、透明度、深淺色自動切換、是否顯示注音 / 註解
- 選字鍵可自訂（1–9、空白、方向鍵）
- 設定 GUI 中即時預覽主題

### 4.12 效能目標 ✅
| 指標 | 目標 |
|------|------|
| 引擎處理單次按鍵 | p99 < 1ms |
| 按鍵 → 候選窗更新完成 | p99 < 一個畫面更新週期（約 8–16ms） |
| 服務程序常駐記憶體（不含 AI） | < 50MB |
- CI 跑效能基準測試，退步即失敗
- **AI 永遠不在同步路徑上**：結果晚到就丟掉或在下一次更新時才顯示

### 4.13 AI 整合 🔶
**三種延遲等級**：

| 等級 | 延遲 | 執行方式 | 用途 |
|------|------|---------|------|
| T0 同步 | < 1ms | 內建極小模型（n-gram 或蒸餾過的小型網路） | 每次按鍵的候選排序 |
| T1 非同步 | 100ms–1s | 本地小型 LLM（llama.cpp / GGUF）❓ | 整句同音錯字修正、續寫提示 |
| T2 指令式 | 數秒 | 本地 LLM 或使用者設定的 OpenAI 相容 API | 選取文字 → 改寫 / 翻譯 / 潤飾 |

- **AI 後端** ✅：統一使用 **OpenAI 相容 API** 介面
  - 同一個介面可接：內建本地執行器、自架服務（Ollama / LM Studio / vLLM 等）、外部雲端 API
  - T0 一律內建本地執行（延遲要求 < 1ms，不能走網路）
  - **T1、T2 可各自指定不同端點**（例如 T1 用本機小模型、T2 用雲端大模型）
- 預設不連任何外部端點；使用者主動設定後才啟用
- 每個端點可設定逾時；逾時或失敗時直接略過 AI 結果，不影響打字
- **送往非本機端點的內容要明確標示**：設定頁顯示「這個端點會收到你的打字內容」
- 可依 App 停用 AI；密碼欄位一律不送
- 讀取游標前後文字（提升準確度）須明確開啟
- API Key 存作業系統鑰匙圈（見 4.8）
- **AI 只在「符合已輸入注音」的候選之間評分**，不自由生成選字結果 → 模型偏簡體 / 中國用語的影響有限

**候選模型**（2026-11 查詢，皆需實測繁中表現）：

| 等級 | 模型 | 授權 | 備註 |
|------|------|------|------|
| T0 | 自行訓練的極小模型（數 MB） | 自有 | 由大型模型蒸餾而來 |
| T1 | Qwen3.5 0.8B / 2B | Apache 2.0 | 2026-03 發佈，4-bit 量化後 < 2GB |
| T1 | Qwen3 0.6B / 1.7B、Gemma 3 270M / 1B | Apache 2.0 / Gemma 授權 | 備選 |
| T2 | Qwen3.5 4B / 9B | Apache 2.0 | |
| T2 | Breeze 7B（聯發科創新基地） | ❓ | 繁中專用詞表；Q4 約 4.5GB |

開發機：RTX 4070 Ti SUPER 16GB → T1 / T2 模型都能在本機跑，也足以訓練 T0 與用 LoRA 微調 T1 模型。

### 4.14 個人化學習訊號 ✅
- 每次選字記錄：前文（本輸入法送出過的前 N 個字）、讀音、**選中的詞**、**當時排第一的詞**
- 「沒選第一個」= 修正訊號，權重最高
- 即時更新使用者模型；本機也能定期用這些訊號微調 T0 模型
- **即時個人首選正確率**：選中第一個的比例，在設定 GUI 顯示趨勢
  - 正確率明顯下降 → 警示，並可一鍵還原到之前的學習快照（對應 P1）
- 離線評測（6.3）仍保留：確保個人學習不會讓整體選字變差

### 4.15 重新選字（Reconversion）🔶
流程：
1. 在 App 中選取文字（或游標停在詞中間），按快捷鍵
2. 讀取文字與前後文：Windows 用 TSF（`ITfFnReconversion` / `ITfRange`），macOS 用 `IMKTextInput`（`selectedRange`、`attributedSubstring`）
3. 推回注音：
   - 若是本輸入法最近送出的文字 → 直接用當時記錄的讀音（最準確）
   - 否則 → 用詞庫反查 + 語言模型選出最可能的讀音
4. 把那段文字變回組字狀態，使用者移動游標、改選字
5. 確認後取代原文，並當作強修正訊號回饋給學習

App 支援度：
- 微軟自家 App、WPF / WinUI 支援度高（日文輸入法的「再変換」功能讓這個機制在 Windows 很普遍）
- Chromium / Electron（含 VS Code）、終端機支援度不一 ❓
- 不支援的 App 可退回剪貼簿方案：複製選取內容 → 組字 → 貼回，並還原剪貼簿（依 App 開啟）
